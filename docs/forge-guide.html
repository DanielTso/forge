forge v0.1.1 · field guide

Start every project with the right bones

forge is a command you type once at the start of a project. In about a second it builds the folder structure, tests, docs, license and automatic checks that professional teams use, so you (and your AI assistant) build on a solid base instead of a pile of loose files.

Go · Python · Node · Rust never overwrites your files preview before it writes
Why this helps when you vibe code

AI writes better code into a good structure

When you ask an AI to "make me an app", it invents a layout every time. Some files land in odd places, there are no tests, and nothing warns you when a change breaks something. forge fixes the starting point: the AI gets a known layout with a working test it can copy, and GitHub runs the checks for you on every push.

Before you start

Install it once

You need Go installed (it is on this machine already). Then one command puts forge on your computer:

terminal
$ go install github.com/DanielTso/forge@latest
$ forge --version
forge v0.1.1 (none)
$ forge list
TYPE        DESCRIPTION
go-cli      Go command-line application …

If forge isn't found after installing, open a new terminal so it picks up Go's install folder (~/go/bin).

No Go? Download a ready-made file for Windows, Mac or Linux from the latest release page, unzip it, and run it.

  5. Prove it works

    The project runs and passes its tests before you write a single line. That gives you (and your AI) a working baseline to compare against.

    Not sure what shortcuts exist? make help lists every one with a short description.

  6. Add pieces later, safely

    Decided you want Docker, CI or a license after the fact? forge add drops in just that piece, matched to your language. Run it twice and it refuses rather than overwrite your work.

    forge add
    $ forge add dockerfile
Added dockerfile to this go-cli project:
  .dockerignore
  Dockerfile

$ forge add dockerfile
Error: 2 file(s) already exist: .dockerignore, Dockerfile (use --force to overwrite)

    Type forge add on its own to see all the pieces: ci, dockerfile, license, gitignore, editorconfig, changelog, contributing, github, docs, makefile, lint.

  Cheat sheet
  
The commands you'll actually use

  

    
Type thisWhat happens

    
      
forge newAsks you questions, then builds the project

      
forge new my-app -t pythonBuilds a Python project in ./my-app right away

      
forge new my-app --dry-runShows what would be created; writes nothing

      
forge initSame as new, but fills the folder you're already in

      
forge addLists pieces you can add to an existing project

      
forge add ci licenseAdds those pieces, matched to the project's language

      
forge listShows project types and licenses

      
make helpInside a project: lists its shortcuts (test, run, lint …)

      
make checkInside a project: format, lint and test in one go

    
  






  Safety net
  
Hard to break things with it

  

    
Never overwritesIf any file already exists, forge stops and writes nothing at all, unless you add --force.

    
Preview first--dry-run on new, init or add shows the plan and marks files that already exist.

    
Works offlineAll templates are built into the program. It never downloads anything or sends your code anywhere.
